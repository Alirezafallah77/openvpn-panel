# OpenVPN Panel — نسخهٔ توسعه

پنل فارسی مدیریت سهمیه برای هدف **Ubuntu 24.04**، با Python، Flask و SQLite.

> **برای استفادهٔ عملیاتی آماده نیست.** پنل وب اکنون کار می‌کند، اما هنوز به OpenVPN متصل نیست: کاربر VPN یا گواهی نمی‌سازد، مصرف واقعی را دریافت نمی‌کند و هیچ اتصال فعالی را قطع نمی‌کند. نصب‌کنندهٔ OpenVPN، تنظیم فایروال و صدور فایل `.ovpn` هنوز ساخته نشده‌اند. این پروژه را جایگزین کنترل دسترسی واقعی سرور نکنید.

## امکانات فعلی

- ورود مدیر با هش scrypt، نشست یک‌ساعته، CSRF، کوکی HttpOnly/SameSite و Secure به‌صورت پیش‌فرض.
- محدودیت سراسری ۱۰ تلاش ورود در پنج دقیقه، در حافظهٔ یک پردازه؛ برای چند worker مناسب نیست و با restart پاک می‌شود. یک مهاجم می‌تواند موقتاً ورود مدیر را محدود کند؛ پنل مدیریت را در شبکهٔ محدود قرار دهید.
- ساخت رکورد کاربر با نام یکتا، حجم GiB و تعداد روز، نمایش مصرف و حجم باقی‌مانده، روزهای سپری‌شده و باقی‌مانده؛ شروع اعتبار با اولین اتصال ثبت‌شده در هسته.
- فعال/غیرفعال‌سازی سهمیه و لینک محرمانهٔ فقط‌خواندنی وضعیت، با امکان ابطال و صدور مجدد.
- توکن تصادفی ۲۵۶ بیتی؛ تنها هش آن در دیتابیس ذخیره می‌شود و لینک فقط هنگام صدور نمایش داده می‌شود.
- حسابداری تراکنشی مجموع دریافت و ارسال با شمارنده‌های تجمعی نشست و جلوگیری از دوباره‌شماری. **هیچ API عمومی برای تغییر شمارنده یا اعلام اتصال وجود ندارد.**

«مجاز» در صفحات فقط وضعیت محاسباتی سهمیه است، نه تأیید اعمال آن روی OpenVPN. لینک وضعیت فایل اتصال یا subscription قابل واردکردن در کلاینت VPN نیست.

## اجرای محلی برای توسعه

دستورها را در پوشهٔ همین مخزن اجرا کنید. نیاز به root برای اجرای برنامه نیست:

```bash
# نصب پیش‌نیاز روی Ubuntu 24.04
sudo apt update
sudo apt install -y python3 python3-venv
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# خروجی هش را به‌طور کامل، شامل علامت‌های $، کپی کنید
.venv/bin/python manage.py password-hash

# مقدار هش را داخل تک‌نقل‌قول بگذارید تا shell آن را تغییر ندهد
export PANEL_PASSWORD_HASH='PASTE_FULL_HASH_HERE'
export PANEL_SECRET="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))')"
umask 077
mkdir -p instance

# فقط برای توسعهٔ محلی روی HTTP؛ کوکی Secure موقتاً غیرفعال است
.venv/bin/python -c 'from app import create_app; create_app({"SESSION_COOKIE_SECURE": False}).run(host="127.0.0.1", port=8000)'
```

آدرس: `http://127.0.0.1:8000`. دیباگر را فعال نکنید و این سرور توسعه را به اینترنت باز نکنید. کلید نشست را برای اجرای پایدار یک بار تولید و امن ذخیره کنید؛ تغییر آن نشست‌های قبلی را باطل می‌کند.

## الزامات استقرار آزمایشی پشت HTTPS

این بخش نصب‌کنندهٔ نهایی نیست. پیش از انتشار عمومی همچنان اتصال‌دهندهٔ VPN و آزمون سرتاسری لازم است.

- برنامه را با کاربر غیر root، کد فقط‌خواندنی و پوشهٔ دیتابیس با دسترسی `0700` اجرا کنید. از `umask 077` استفاده کنید؛ فایل دیتابیس باید `0600` باشد.
- متغیرهای `PANEL_SECRET`، `PANEL_PASSWORD_HASH`، `PANEL_DATABASE` (ترجیحاً مسیر مطلق) و `PANEL_HOST` (مثلاً `panel.example.com`، بدون scheme/path) را در فایل محیطی محافظت‌شده خارج از مخزن ذخیره کنید.
- HTTPS را با reverse proxy معتبر خاتمه دهید، فقط پورت ۴۴۳ را برای پنل باز کنید و Gunicorn را روی loopback نگه دارید. فقط **یک worker** استفاده کنید:

```bash
umask 077
.venv/bin/gunicorn --workers 1 --threads 4 --bind 127.0.0.1:8000 'app:create_app()'
```

- proxy باید Host صحیح را حفظ و `X-Forwarded-Proto: https` را خودش تنظیم کند؛ پورت backend را عمومی نکنید. ProxyFix عمداً فعال نیست. در Gunicorn تنها proxy محلی مجاز باشد؛ `forwarded-allow-ips=*` تنظیم نکنید. Secure بودن کوکی را در استقرار HTTPS خاموش نکنید.
- در proxy و هر سرویس واسط، ثبت مسیرهای `/s/` را خاموش کنید. Gunicorn به‌صورت پیش‌فرض access log ندارد؛ آن را بدون حذف توکن فعال نکنید. لینک توکن‌دار را به ابزارهای تحلیل، لاگ و سرویس‌های خارجی نفرستید. پاسخ‌ها `no-store` و `no-referrer` هستند؛ نگهداری امن لینک همچنان ضروری است.
- از کپی دیتابیس حین نوشتن با `cp` اجتناب کنید؛ سرویس را متوقف کنید یا از API پشتیبان‌گیری SQLite استفاده کنید. پشتیبان‌ها اطلاعات خصوصی دارند و باید رمزگذاری و بازیابی آن‌ها آزمایش شود.
- نشست‌های مدیر فعلاً ابطال مرکزی ندارند؛ برای خروج همهٔ مدیرها `PANEL_SECRET` را عوض و سرویس را restart کنید. برای تغییر رمز، هش جدید را تنظیم و هم‌زمان کلید نشست را عوض کنید.

## آزمون‌ها

```bash
.venv/bin/python -m unittest discover -s tests -v
```

۱۲ آزمون برای حسابداری، هم‌زمانی، شروع اعتبار، اتمام حجم، توکن، ورود، CSRF، اعتبارسنجی ورودی، محدودیت ورود و هدرهای امنیتی موجود است. آزمون‌ها در محیط توسعه اجرا شده‌اند؛ CI برای Ubuntu 24.04 و Python 3.12/3.13 تعریف شده اما نتیجهٔ آن باید پس از push بررسی شود. آزمون نصب واقعی یا OpenVPN انجام نشده است.

## مراحل بعدی پیش از نسخهٔ قابل نصب

1. اتصال‌دهندهٔ قابل اعتماد OpenVPN: گواهی/ابطال، پذیرش اتصال، ثبت نشست و شمارنده‌های زنده، بازیابی پس از restart.
2. قطع نشست فعال پس از اتمام حجم/روز، بررسی دوره‌ای حتی بدون ترافیک، تعیین فاصلهٔ نمونه‌برداری و سقف تجاوز، سیاست fail-closed.
3. نصب‌کنندهٔ بازاجرایی امن Ubuntu 24.04، systemd، TLS، شبکه، مسیریابی و فایروال بدون آسیب به SSH؛ ارتقا و حذف امن.
4. ثبت رویداد بدون اسرار، مهاجرت دیتابیس، تست پشتیبان‌گیری/بازیابی و آزمون عملی قطع ناگهانی و چند نشست.

تغییرات این جلسه روی شاخهٔ موجود `arena/c09c103f-openvpn-panel` نگهداری می‌شوند؛ نیازی به ساخت مخزن یا تغییر نام شاخه نیست.
