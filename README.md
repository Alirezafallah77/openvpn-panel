# OpenVPN Panel • نسخهٔ آزمایشی 0.4

پنل فارسی و راست‌به‌چپ برای **نصب جدید OpenVPN روی Ubuntu 24.04**.

ساخت کاربر، فایل اتصال `.ovpn`، سهمیهٔ مجموع ارسال و دریافت، اعتبار از اولین پذیرش اتصال، نمایش مصرف و روزهای باقی‌مانده، لینک محرمانهٔ وضعیت، فعال/غیرفعال‌سازی، و قطع اتصال پس از اتمام سهمیه.

> این نسخه هنوز آزمایشی است، نه محصول ممیزی‌شده. ابتدا روی VPS تازه و غیرعملیاتی امتحان کنید. نتیجهٔ آزمون خودکار نصب و اتصال واقعی را در [GitHub Actions](https://github.com/Alirezafallah77/openvpn-panel/actions) بررسی کنید. آزمون روی یک VPS واقعی شما، دامنه، فایروال شرکت میزبان و کلاینت‌های موبایل جداگانه لازم است.

## امکانات جدید 0.3: SSL Management و UDP/TCP

پس از ارتقا، در داشبورد **SSL Management / OpenVPN Protocol** را باز کنید.

- برای فعال‌کردن HTTPS بعد از نصب بدون دامنه، دامنه را وارد کنید. رکورد A باید به همین سرور اشاره کند و TCP 80/443 باز باشد. Caddy گواهی را خودکار می‌گیرد و تمدید می‌کند؛ تاریخ انقضا و اعتبار زنجیرهٔ TLS در صفحه نمایش داده می‌شود.
- گزینهٔ «همین دامنه در فایل‌های جدید VPN» به‌صورت پیش‌فرض روشن است. در صورت نیاز، دامنهٔ پنل و دامنه/IP اتصال VPN را جدا نگه دارید. فایل‌های دانلودشدهٔ قبلی خودکار تغییر نمی‌کنند.
- برای تغییر پروتکل، UDP یا TCP را انتخاب کنید و با رمز مدیر و تأیید قطعی ذخیره کنید. کاربران و مصرف و اعتبار حفظ می‌شوند، ولی اتصال فعال قطع می‌شود و فایل کلاینت جدید لازم است. فعلاً یک پروتکل هم‌زمان و همان پورت فعلی (پیش‌فرض 1194) پشتیبانی می‌شود.
- پورت HTTPS پنل **TCP 443** است؛ پورت اتصال VPN با تغییر پروتکل عوض نمی‌شود. برای TCP، TCP 1194 و برای UDP، UDP 1194 را در فایروال میزبان باز کنید.
- اگر Cloudflare دارید و دامنه را برای VPN هم استفاده می‌کنید، DNS آن باید **DNS only** باشد؛ پروکسی معمولی وب، OpenVPN را عبور نمی‌دهد.

تغییرات در یک سرویس root جداگانه اعمال می‌شوند. HTTPS جدید فقط پس از تأیید گواهی و پاسخ پنل فعال می‌شود. در خطای عادی، تنظیمات قبلی برمی‌گردند؛ بازیابی اضطراری از SSH:

```bash
sudo openvpn-panelctl settings-rollback
```

این دستور آخرین snapshot تنظیمات دامنه/شبکه را برمی‌گرداند و VPN و وب را دوباره راه‌اندازی می‌کند. کاربران/مصرف پاک نمی‌شوند. Caddy تنها اگر متعلق به همین نصب باشد مدیریت می‌شود؛ تنظیمات سرویس وب دیگری بی‌اجازه جایگزین نمی‌شود. روی نصب SSH تازه نیز پکیج Caddy نصب است، ولی تا فعال‌کردن HTTPS سرویس آن خاموش می‌ماند.

## ساده‌ترین نصب

نیازمندی‌ها: Ubuntu **24.04** تازه، دسترسی `sudo`، IPv4 عمومی، TUN فعال و بدون OpenVPN یا سرویس وب دیگر. پیش‌فرض‌ها: UDP **1194**، شبکهٔ VPN `10.87.0.0/24`، پنل فقط روی loopback پورت **8000**.

روی سرور (به‌جای `YOUR_SERVER_IP` آدرس واقعی بگذارید):

```bash
sudo apt update && sudo apt install -y git
# تا زمان ادغام، حتماً همین شاخه را دریافت کنید:
git clone --branch arena/c09c103f-openvpn-panel --single-branch https://github.com/Alirezafallah77/openvpn-panel.git
cd openvpn-panel
sudo bash scripts/install.sh --endpoint YOUR_SERVER_IP
```

هنگام نصب، رمز مدیریت را دو بار وارد می‌کنید؛ حداقل ۱۲ کاراکتر. **در فایروال میزبان VPS پورت UDP 1194 را باز کنید.** نصب‌کننده عمداً پورت SSH، سیاست INPUT یا قوانین موجود میزبان را تغییر نمی‌دهد. وجود UFW/firewalld فعال یا نصب قبلی باعث توقف امن نصب می‌شود؛ بدون بررسی فایروال قبلی را خاموش نکنید.

### بازکردن پنل، بدون دامنه

روی **کامپیوتر خودتان**، نه سرور:

```bash
ssh -N -L 8000:127.0.0.1:8000 root@YOUR_SERVER_IP
```

اگر با کاربر دیگری SSH می‌زنید، `root` را عوض کنید. این ترمینال را باز نگه دارید و در مرورگر وارد **http://localhost:8000** شوید؛ رمز نصب را وارد کنید.

۱. نام انگلیسی، حجم GiB و تعداد روز را وارد و کاربر بسازید.
۲. لینک محرمانهٔ وضعیت را کپی کنید؛ فقط هنگام صدور نمایش داده می‌شود.
۳. دکمهٔ **دانلود فایل اتصال** را بزنید و فایل را به OpenVPN Connect یا کلاینت سازگار با OpenVPN 2.5+ بدهید.
۴. اعتبار زمانی هنگام اولین پذیرش اتصال پس از احراز گواهی شروع می‌شود. سقف اتصال هم‌زمان هر کاربر در ساخت و ویرایش قابل انتخاب است (۱ تا ۱۰۰، پیش‌فرض ۱). مثلاً سقف ۲، اتصال سوم همان کانفیگ را رد می‌کند؛ حجم و اعتبار بین اتصال‌ها مشترک است.

**نکته:** در حالت SSH، لینک‌های وضعیت `localhost` هستند و فقط برای فردی با تونل به همان سرور کار می‌کنند. برای لینک قابل‌اشتراک به کاربران، نصب با دامنه و HTTPS را انتخاب کنید.

## نصب با پنل و لینک وضعیت عمومی HTTPS

قبل از نصب، رکورد DNS نوع A دامنهٔ پنل را به IPv4 سرور تنظیم کنید، رکورد AAAA اشتباه نداشته باشید و TCP **80/443** و UDP **1194** را در فایروال شرکت میزبان باز کنید. سپس روی سرور تازه:

```bash
sudo bash scripts/install.sh --endpoint YOUR_SERVER_IP --domain panel.example.com
```

پنل و لینک‌های وضعیت روی `https://panel.example.com` در دسترس خواهند بود. Caddy گواهی TLS را خودکار می‌گیرد و تمدید می‌کند. به‌جای IP در `--endpoint` می‌توانید نام DNS سرور VPN بدهید؛ endpoint باید IPv4 یا دامنه با رکورد A باشد. حالت HTTP عمومی پشتیبانی نمی‌شود.

## رفتار سهمیه و محدودیت‌های مهم

- هر GiB برابر `1024³` بایت است. حجم، مجموع شمارنده‌های دریافت و ارسال گزارش‌شده توسط OpenVPN است؛ با حجم payload برنامه‌ها یا صورت‌حساب میزبان الزاماً برابر نیست.
- زمان بر اساس UTC و هر روز دقیقاً ۲۴ ساعت است، **نه تعداد روزهایی که ترافیک داشته‌اید**. از اولین پذیرش تونل به‌صورت پیوسته می‌گذرد. ساخت کاربر/دانلود فایل زمان را شروع نمی‌کند. hook پذیرش ممکن است پیش از تکمیل تنظیم شبکهٔ کلاینت اجرا شود؛ در آن حالت هم اعتبار آغاز شده است.
- حسابداری و بررسی تاریخ انقضا هر **۲ ثانیه** انجام می‌شود. قطع فعال لحظه‌ای و سقف حجم سخت بایت‌به‌بایت نیست: تأخیر مدیریت/قطع نیز اضافه می‌شود. در سرعت بالا امکان عبور از سهمیه وجود دارد؛ سقف بایتی ثابتی برای این تجاوز تضمین نشده است.
- قطع عادی شمارندهٔ نهایی را ثبت می‌کند. در قطع ناگهانی پردازه یا برق، ترافیک از آخرین نمونه تا خرابی ممکن است ثبت نشود. این نسخه برای صورتحساب مالی دقیق مناسب نیست.
- خرابی حسابداری باعث توقف OpenVPN از طریق systemd می‌شود؛ پذیرش اتصال نیز heartbeat تازه می‌خواهد. پس از رفع خطا `sudo openvpn-panelctl restart` را اجرا کنید. نبود heartbeat پس از حدود ۱۵ ثانیه اتصال جدید را رد می‌کند؛ توقف systemd پس از تشخیص خرابی اعمال می‌شود؛ watchdog پانزده‌ثانیه‌ای، توقف پردازش حسابداریِ زنده اما گیرکرده را نیز بررسی می‌کند.
- ویرایش سهمیه، سقف کل حجم و کل روزها را تغییر می‌دهد؛ مصرف و زمان شروع پاک نمی‌شوند. با افزایش سقف، کاربر دارای سهمیهٔ مجاز می‌تواند دوباره وصل شود. غیرفعال‌سازی دستی با افزایش سهمیه لغو نمی‌شود.
- «تعویض کلید و دانلود» گواهی قبلی را ابطال و قطع آن را درخواست می‌کند. فایل جدید را به کاربر بدهید؛ فایل قبلی دیگر برای اتصال مجدد معتبر نیست. عملیات صدور/ابطال با قفل سریالی انجام می‌شود؛ در صورت خطای دیسک/PKI، دانلود را تکرار و لاگ سرویس PKI را بررسی کنید.
- لینک وضعیت یک توکن محرمانهٔ فقط‌خواندنی است، **نه فایل اتصال VPN یا ساب قابل واردکردن در کلاینت**. هرکس آن را داشته باشد مصرف را می‌بیند؛ از پنل می‌توانید لینک قبلی را باطل کنید.
- VPN دسترسی به اینترنت IPv4 می‌دهد. IPv6 داخل تونل مسدود می‌شود، شبکه‌های خصوصی/metadata و سرویس‌های خود سرور از تونل قابل دسترسی نیستند. رفتار IPv6، DNS و قطع تونل در کلاینت‌ها را آزمایش کنید؛ این پروژه kill switch سیستم‌عامل کلاینت نصب نمی‌کند. کلاینت خط فرمان لینوکس ممکن است تنظیم DNS سیستم را خودکار اعمال نکند.
- اعتبار CA و گواهی‌ها حداکثر ده سال است؛ تمدید خودکار PKI در این نسخه وجود ندارد. Caddy فقط گواهی وب را تمدید می‌کند.

## نگهداری و عیب‌یابی

```bash
sudo openvpn-panelctl status
sudo openvpn-panelctl restart
sudo openvpn-panelctl password
sudo openvpn-panelctl backup /root/openvpn-panel-backup.ovpnbak
sudo openvpn-panelctl restore /root/openvpn-panel-backup.ovpnbak
sudo openvpn-panelctl web-start
```

رمز جدید، نشست‌های مدیریت قبلی را هم باطل می‌کند. بکاپ جدید وب و تلگرام بدون رمز فایل است. در صفحهٔ بکاپ، فایل را آپلود کنید و با رمز فعلی مدیر و تأیید جایگزینی، بازیابی را انجام دهید؛ داشبورد فقط پس از موفقیت تازه می‌شود. برای فایل‌های رمزدار قدیمی، رمز اصلی هنوز لازم است. روش SSH نیز برای بازیابی اضطراری باقی است. پشتیبان حاوی **کلید CA، کلید خصوصی کاربران و اطلاعات محرمانه** است؛ آن را محرمانه و خارج از دسترس دیگران نگهداری کنید؛ هرکس بکاپ جدید را داشته باشد می‌تواند محتوای آن را بخواند. بازگردانی و رفع نصب نیمه‌تمام در [راهنمای عملیات](docs/OPERATIONS.md) توضیح داده شده است.

```bash
sudo journalctl -u openvpn-panel -u openvpn-panel-pki -u openvpn-panel-accounting -u openvpn-server@panel -n 100 --no-pager
```

لاگ‌ها ممکن است نام کاربر و IP اتصال را داشته باشند؛ بی‌نام‌سازی کنید و عمومی منتشر نکنید. هیچ‌گاه فایل `.ovpn`، `.env`، دیتابیس یا فایل پشتیبان را برای پشتیبانی ارسال نکنید.

## معماری و امنیت

- وب با کاربر غیر root، کد root-owned و filesystem فقط‌خواندنی اجرا می‌شود؛ بدون `sudo` و بدون دسترسی به CA. سرویس مجزای PKI/نگهداری درخواست‌ها را از سوکت Unix با بررسی UID و نام معتبر می‌پذیرد؛ عملیات مجاز از فهرست ثابت هستند. دسترسی شبکهٔ این سرویس برای ارسال دستی تلگرام لازم است.
- OpenVPN و حسابداری در این نسخه root هستند و با تنظیمات systemd محدود می‌شوند؛ compromise ریشهٔ سرور یا مدیر پنل همچنان خطر جدی است. CA آنلاین و بدون passphrase برای صدور خودکار نگهداری می‌شود.
- گواهی متقابل TLS، `tls-crypt`، حداقل TLS 1.2، رمزهای AEAD، عدم compression و CRL؛ کاربران ناشناخته/غیرمجاز توسط hook پذیرش رد می‌شوند.
- رمز مدیر scrypt، نشست یک‌ساعته، CSRF، Secure cookie در حالت HTTPS، HttpOnly و SameSite، CSP، no-store و no-referrer؛ اعتبارسنجی توکن وضعیت با هش SHA-256 است؛ نسخهٔ جدید برای کپی مجدد، یک نسخهٔ رمزنگاری‌شدهٔ جداگانه هم نگه می‌دارد.
- محدودیت ورود، سراسری و در حافظهٔ **یک worker** است: ۱۰ تلاش در پنج دقیقه. restart آن را پاک می‌کند و مهاجم می‌تواند ورود را موقتاً محدود کند. پنل SSH پیش‌فرض، امن‌تر از انتشار عمومی آن است. چند worker بدون throttle مشترک پشتیبانی نمی‌شود.
- پنل و Caddy عمداً access log مسیرها ندارند تا توکن وضعیت ثبت نشود؛ فعال‌کردن لاگ در proxy دیگر بدون حذف `/s/…`، اسرار را افشا می‌کند. خطاهای reverse proxy هنگام خاموش‌بودن وب ممکن است URI را در journal ثبت کنند؛ journal را محرمانه نگه دارید و قبل از اشتراک‌گذاری، مسیرها/توکن‌ها را حذف کنید.
- نصب‌کننده فقط زنجیره‌های اختصاصی شبکه را می‌سازد، IPv4 forwarding را فعال می‌کند و از flush کلی فایروال پرهیز می‌کند. **تنها برای سرور تازه و اختصاصی** طراحی شده؛ تکرار نصب روی دادهٔ قبلی را عمداً رد می‌کند.

## توسعه و آزمون

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
bash -n scripts/install.sh
```

workflow آزمون واحد روی Ubuntu 24.04/Python 3.12 و 3.13، و workflow جداگانهٔ نصب واقعی با systemd، namespace شبکه و کلاینت OpenVPN وجود دارد. آزمون سرتاسری **مخرب و صرفاً برای runner یک‌بارمصرف** است؛ آن را روی سرور خود اجرا نکنید.

برای اجرای وب توسعه، با `manage.py password-hash` هش بسازید، `PANEL_SECRET` تصادفی حداقل ۳۲ کاراکتری و `PANEL_PASSWORD_HASH` را تنظیم کنید، سپس:

```bash
PANEL_LOCAL_HTTP=1 .venv/bin/python -m flask --app 'app:create_app()' run --host 127.0.0.1 --port 8000
```

بدون `PANEL_VPN_CONFIGURED=1` صفحات در حالت توسعه و بدون اتصال واقعی به VPN هستند. متغیرهای نصب واقعی در `/etc/openvpn-panel/panel.env` قرار دارند و نباید وارد Git شوند.

گزارش آزمون‌های اجراشده و محدودیت پوشش: [docs/TESTING.md](docs/TESTING.md).


## نسخهٔ 0.4 — پورتال مشترک و عیب‌یابی SSL

ظاهر فارسی و واکنش‌گرا با فونت Vazirmatn محلی (بدون CDN)، تب‌های قابل استفاده با کیبورد، و نمایش جداگانهٔ حجم/زمان کل، مصرف‌شده و باقی‌مانده. لینک `/s/<token>` حالا پورتال مشترک است: دانلود فایل .ovpn با POST و CSRF، بدون ورود مدیر و بدون امکان تعویض کلید، به‌علاوهٔ راهنمای Android، iOS/iPadOS و Windows. دانلود برای کاربر غیرفعال/منقضی/بدون حجم رد می‌شود و rate limit دارد. دانلود فایل اعتبار را شروع نمی‌کند.

**تغییر امنیتی مهم:** لینک‌های وضعیت قبلی نیز پس از این ارتقا امکان دانلود فایل خصوصی اتصال را خواهند داشت. لینک‌های افشاشده را با «صدور لینک اشتراک جدید» باطل کنید و لینک تازه را فقط برای صاحب اشتراک بفرستید. لینک‌های قدیمیِ فقط‌هش قابل بازیابی نیستند؛ نسخهٔ جدید لینک‌های ساخته/صادرشده را رمزنگاری می‌کند تا مدیر بتواند بدون ابطال دوباره کپی کند. صدور لینک جدید، کلید VPN را عوض نمی‌کند؛ برای ابطال فایل لو‌رفته باید «تعویض کلید و دانلود» را هم انجام دهید. این پورتال لینک ایمپورت خودکار V2Ray/Clash نیست؛ فایل استاندارد OpenVPN دانلود می‌دهد.

SSL اکنون مرحله و کد خطا (`caddy_validate`، `caddy_start`، `tls_certificate`، `web_restart`، `panel_https`) را ثبت می‌کند. مهلت صدور ۱۸۰ ثانیه و بررسی پاسخ پنل ۳۰ ثانیه است. تأخیر HTTP دیگر گواهی معتبر را اشتباهاً نامعتبر نشان نمی‌دهد و خواندن تکه‌تکهٔ خط وضعیت HTTP پشتیبانی می‌شود. لاگ traceback فقط در journal روت است؛ جزئیات خام دستورات/محیط به وب ارسال نمی‌شود. این تغییرات به‌تنهایی خرابی DNS، فایروال یا محدودیت ACME روی VPS را حل نمی‌کنند؛ علت خطای قبلی بدون لاگ قابل اثبات نیست.


**رفع باگ شروع SSL از حالت SSH/IP:** روی Ubuntu 24.04 بازتولید شد که `systemctl reset-failed caddy.service` برای سرویس خاموش و unload‌شده exit 1 می‌دهد و قبل از شروع Caddy کار را متوقف می‌کند. اکنون فقط اگر `is-failed` واقعاً مثبت باشد reset انجام می‌شود؛ سرویس خاموش مستقیماً start می‌شود. همین الگو برای راه‌اندازی مجدد وب هم اعمال شده است. این ایراد مستقل از درست‌بودن DNS رخ می‌داد؛ DNS/ACME سرور واقعی همچنان باید معتبر باشد.

### ساخت سریع و پشت‌سرهم کاربران

پیش‌فرض ساخت کاربر **50 GiB / 30 روز** است (در فرم و در سرور وقتی این دو فیلد ارسال نشوند). با JavaScript ساخت در همان داشبورد انجام می‌شود؛ بعد از موفقیت نام خالی و متمرکز می‌شود و حجم/مدت انتخابی حفظ می‌گردد. کارت لینک‌های همین نوبت در صفحه می‌ماند؛ کپی لینک، بازکردن اشتراک در تب جدید و در حالت پیکربندی‌شده دانلود فایل در دسترس است. لینک‌ها در localStorage/sessionStorage یا session مدیر ذخیره نمی‌شوند ؛ کارت‌های همان نوبت پس از بازخوانی پاک می‌شوند، ولی لینک‌های جدید از آیکون کپی قابل دریافت‌اند. آمار اصلی با به‌روزرسانی داشبورد تازه می‌شود.

بدون JavaScript هم پس از ساخت، فرم کاربر بعدی کنار لینک نتیجه نمایش داده می‌شود. خطای نام تکراری مقادیر انتخابی را نگه می‌دارد. ارسال تکراری هنگام انتظار غیرفعال است؛ اگر ارتباط قطع شد یا نشست منقضی شد، پیش از ارسال مجدد فهرست کاربران را بررسی کنید (ممکن است درخواست اول انجام شده باشد). هیچ درخواست ناموفق به‌صورت خودکار تکرار نمی‌شود. اعتبار همچنان از اولین اتصال شروع می‌شود.

### داشبورد تیره و صفحه‌بندی کاربران

داشبورد مدیریت با پوستهٔ تطبیقی روشن/تیره، کارت‌های رنگی و نشانگر **واقعیِ مقدار فعلی** منابع طراحی شده است؛ نمودار تاریخچه یا وضعیت سرویس ساختگی ندارد. پوستهٔ روشن هم از دکمهٔ بالای صفحه قابل انتخاب است؛ فقط ترجیح ظاهری در localStorage ذخیره می‌شود. پورتال مشترک مستقل مانده و فرم ساخت سریع 50 GiB / 30 روز حفظ شده است.

لیست کاربران به‌صورت پیش‌فرض ۲۰ ردیف دارد؛ ۵۰ و ۱۰۰ نیز قابل انتخاب‌اند. انتخاب تعداد تا پایان نشست مدیر باقی می‌ماند. جست‌وجو/فیلتر قبل از صفحه‌بندی اعمال می‌شوند؛ آمار کل، مستقل از صفحه و فیلتر است. فیلترهای نزدیک پایان حجم (حداکثر ۱۰٪ باقی‌مانده) و اعتبار (حداکثر ۳ روز) فقط کاربران مجاز را نشان می‌دهند. وضعیت آنلاین نامشخص، با آفلاین یکی فرض نمی‌شود. صفحهٔ نامعتبر محدود می‌شود و ویرایش سهمیه/فعال‌سازی از جدول، صفحه و فیلتر را حفظ می‌کند. صفحه‌بندی فعلاً در لایهٔ نمایش است؛ محاسبهٔ آمار همچنان وضعیت همهٔ کاربران را می‌خواند.


پوستهٔ مدیر: اولویت با انتخاب دستی ذخیره‌شده است؛ اگر انتخابی نباشد از `prefers-color-scheme` دستگاه خوانده می‌شود و در نبود پشتیبانی، **لایت** است. تغییر تنظیم دستگاه تا قبل از انتخاب دستی دنبال می‌شود. دکمهٔ بالای صفحه انتخاب روشن/تیره را نگه می‌دارد. تشخیص اولیه پیش از CSS اجرا می‌شود تا نمایش لحظه‌ای تم اشتباه کاهش یابد؛ بدون JavaScript هم CSS از تنظیم دستگاه پیروی می‌کند و مبنای پیش‌فرض روشن است. پورتال مشترک فعلاً ظاهر مستقل قبلی را حفظ کرده است.

CPU اکنون با نمونهٔ یک‌ثانیه‌ای و cache مشترک سه‌ثانیه‌ای در هر worker خوانده می‌شود؛ نمونهٔ کوتاه ۰٫۱ ثانیه حذف شد. کارت‌های منابع از مسیر فقط‌مدیر `/api/metrics` هر پنج ثانیه، بدون بازخوانی صفحه، تازه می‌شوند. در تب مخفی polling متوقف و با برگشت به صفحه از سر گرفته می‌شود. صفر واقعی حفظ می‌شود؛ خطای خواندن CPU به‌صورت نامشخص و قطع polling به‌صورت هشدار قدیمی‌بودن داده نمایش داده می‌شود. این آمار کل CPU قابل مشاهدهٔ VPS است، نه CPU یک پردازش یا تضمین سهم هایپروایزر.


### میانبرهای مستقیم کاربران

سه آیکون **ویرایش، کپی لینک ساب و حذف** همیشه در ستون مدیریت هستند، بیرون از «عملیات بیشتر». ویرایش و حذف با dialog باز می‌شوند؛ بدون JavaScript به صفحهٔ مستقل می‌روند. حذف فقط تأیید «مطمئنم / بیخیال» دارد و نیازی به تایپ نام نیست. کاربر از لیست حذف، لینک باطل و اتصال توسط چرخهٔ حسابداری قطع می‌شود؛ سوابق برای حسابداری باقی می‌مانند. همان نام دوباره قابل ساخت است، اما حساب جدید لینک و گواهی جدید دارد؛ تا صدور گواهی جدید ورود بسته است و گواهی قدیمی هم در CRL باطل و هم با اتصال شمارهٔ سریال به نسل جدید حساب رد می‌شود. حجم کل ترافیک تاریخی حفظ می‌شود. بازگردانی بکاپ قدیمی ممکن است کاربر حذف‌شده را برگرداند.

کپی، لینک جدید یا دوباره‌صادرشده را **بدون تعویض توکن** می‌خواند. برای کاربران قدیمی، قبل از صدور لینک قابل کپی یک‌بار تأیید ابطال لینک قبلی گرفته می‌شود؛ انصراف هیچ تغییری نمی‌دهد. در HTTP یا نبود مجوز clipboard، لینک برای کپی دستی انتخاب می‌شود.

نسخهٔ قابل کپیٔ توکن با Fernet در ستون `encrypted_token` است و هش برای اعتبارسنجی عمومی باقی می‌ماند. کلید مستقل در `/var/lib/openvpn-panel/quota.sqlite.links.key` با mode 0600 و مالک وب ساخته می‌شود؛ در session/localStorage ذخیره نمی‌شود و با تعویض رمز مدیر عوض نمی‌شود. **فایل کلید را حذف نکنید.** نبود کلید، توکن‌های فعلی را باطل نمی‌کند اما کپی/ساخت لینک جدید را متوقف می‌کند تا کلید درست بازیابی شود. بکاپ جدید DB و این کلید را همراه هم می‌برد و restore مالکیت را اصلاح می‌کند. مقصد را پیش از import این بکاپ به نسخهٔ جدید ارتقا دهید؛ نگه‌داشتن ciphertext و کلید کنار هم در یک بکاپ، جایگزین رمزگذاری خود بکاپ نیست. فایل tar.gz خام شامل اسرار است. downgrade کد قدیمی با DB جدیدِ دارای کاربر حذف‌شده توصیه نمی‌شود؛ برای rollback از نسخهٔ سازگار کد و بکاپ استفاده کنید.


### تمدید و ریست دورهٔ کاربر

در ویرایش، مصرف و تاریخ پایان فعلی نمایش داده می‌شود. «تعیین اعتبار از همین لحظه به تعداد روز» تاریخ را با تعداد روز جایگزین می‌کند؛ ذخیرهٔ ۳۰ روز یعنی ۳۰ روز از همین الآن، نه از اولین اتصال قدیمی. این ذخیره مصرف را صفر نمی‌کند. برای شروع یک دورهٔ کامل، تعداد روز و حجم کل را تنظیم و **ریست مصرف و تمدید از الآن** را بزنید: مصرف صفر، اعتبار از زمان ذخیره و حساب فعال می‌شود. اگر تاریخ نشان داده می‌شود، اولین کلیک ریست، فیلد روز را برای بررسی باز می‌کند؛ کلیک بعدی درخواست را ثبت می‌کند. شمارهٔ گواهی، فایل و لینک ساب تغییر نمی‌کنند. مصرف تاریخی در مجموع ترافیک حفظ می‌شود؛ شمارندهٔ تجمعی نشست زنده صفر نمی‌شود تا مصرف قبلی دوباره شارژ نشود.

کاربر تازه، تا وقتی تمدید صریح از الآن انجام ندهید، همچنان اعتبارش از **اولین اتصال موفق** شروع می‌شود. تاریخ اولین اتصال برای سابقه ثابت است و شروع دورهٔ تمدید جدا نگه داشته می‌شود. حذف و ساخت مجدد، جایگزین تمدید نیست و **فایل جدید** می‌خواهد. بکاپ‌های قدیمی پس از restore مهاجرت داده می‌شوند؛ برای بازگشت به کد قدیمی از بکاپ و کد سازگار استفاده کنید، نه downgrade مستقیم پایگاه جدید.

در ویرایش، علت امن آخرین پذیرش/رد اتصال و زمان آن نمایش داده می‌شود: پایان حجم/زمان، غیرفعال، سقف اتصال، گواهی قدیمی، تعویض کلید یا آماده نبودن حسابداری. این گزارش شامل کلید، توکن یا IP نیست. خطای TLS/CRL پیش از اجرای hook ممکن است در این گزارش ثبت نشود؛ «آخرین اتصال پذیرفته شد» به معنی سلامت همهٔ اتصال‌های بعدی نیست.
