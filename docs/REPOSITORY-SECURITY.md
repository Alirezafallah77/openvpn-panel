# امنیت دسترسی مخزن

عمومی‌بودن مخزن به دیگران اجازهٔ دیدن/clone/fork و پیشنهاد Pull Request می‌دهد؛ به‌تنهایی اجازهٔ push یا merge نمی‌دهد. کد یک fork یا PR تا زمانی که فرد/اپ مجاز آن را ادغام نکند وارد برنچ شما نمی‌شود. عمومی‌بودن همچنین یعنی دیگران می‌توانند نسخه‌ای مستقل از کد داشته باشند؛ عمومی‌سازی گذشته با private کردن، نسخه‌های قبلی را پس نمی‌گیرد.

بررسی فقط‌خواندنی این نوبت (2026-10-31): فهرست collaborators تنها `Alirezafallah77` با نقش admin را نشان داد. فهرست rulesets قابل مشاهده خالی بود؛ APIهای classic branch protection و deploy keys برای اتصال فعلی 403 دادند. این اطلاعات اثبات نبودن توکن، اپ، کلید نوشتنی یا محافظت کلاسیک نیست. این بررسی هیچ دسترسی، visibility یا تنظیم امنیتی مخزن را تغییر نداده است.

پیشنهاد برای مالک:

1. 2FA یا passkey را برای حساب فعال کنید؛ کد بازیابی را بیرون از مخزن نگه دارید.
2. Settings → Collaborators را بازبینی و افراد ناشناس را حذف کنید.
3. در تنظیمات حساب، SSH keys، Personal access tokens، Authorized OAuth Apps و نصب‌های GitHub Apps را بررسی کنید؛ هر مورد غیرضروری/مشکوک را revoke کنید. دسترسی محیط عامل هم از همین مجوزهای تنظیم‌شده می‌آید؛ عمومی‌بودن مخزن به عوامل دیگر دسترسی نوشتن نمی‌دهد.
4. در Settings مخزن، Deploy keys و GitHub Apps را بررسی کنید. کلید deploy در صورت نیاز فقط خواندنی باشد. توکن VPS برای pull به مجوز write نیاز ندارد.
5. برای `master` یک ruleset/branch protection فعال کنید: ممنوعیت force-push و حذف، نیاز به PR و موفقیت تست‌ها. برای اجبار تأیید review، وجود reviewer مستقل و مورداعتماد را در نظر بگیرید؛ الزام تأیید با یک مالک تنها ممکن است روند merge را متوقف کند. روی برنچ کاری عامل محدودیت ناگهانی نگذارید مگر فرآیند push/PR را هماهنگ کرده باشید.
6. رمز پنل، SSH، فایل .env، توکن، دیتابیس واقعی، بکاپ و فایل کلید را وارد Git نکنید. `.gitignore` مانع قطعی نشت یا محافظ فایل ازپیش‌trackشده نیست. اگر راز وارد تاریخچه شده است، **اول rotate/revoke** کنید؛ حذف فایل از آخرین commit کافی نیست.
7. تغییرات PRهای ناشناس، اسکریپت install/upgrade و workflowها را قبل از اجرای کد یا merge بازبینی کنید. برای نصب روی VPS فقط از نسخه/commit مورداعتماد استفاده کنید.

امنیت مطلق تضمین‌شدنی نیست؛ فردی که حساب مالک، توکن نوشتنی، کلید یا اپ مجاز را در اختیار بگیرد می‌تواند در محدودهٔ همان مجوزها تغییر ایجاد کند.
